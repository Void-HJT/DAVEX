数据价值交换平台旨在为解决共享机制不健全带来的数据汇聚难问题，通过采用隐私计算技术对敏感数据进行加密和匿名化处理等保护机制，研发保障数据隐私和安全的数据加密接口，并使用可证明安全计算技术保障数据处理的安全性和可审计性。<br />该数据交换平台为处理金融案件提供了一个全新的协作范式。金融犯罪的复杂性要求各个执法部门之间必须有高度的信息共享和协同能力。通过这个平台，法院、检察院、司法行政部门能够更加高效地共享案件信息，进行研判分析，共同作出决策。<br />该平台旨在实现多部门之间的数据协同，各个部门可以将数据本体存放于本地，利用数据价值交换中心与数据交换代理，实现多部门之间的文件传输、隐私信息检索、隐私计算等多个功能。该数据交换中心与交换代理建立在区块链上，结合区块链技术，该平台为数据的每一次请求和结果都在不可篡改的区块链上进行记录，这为信息追踪、审核和责任追溯提供了强有力的技术支撑。这种透明化处理机制不仅确保了整个司法审判和监督过程的公正性和合法性，还增强了整个系统的信任度和责任清晰性。同时，借助区块链技术的去中心化特性降低了对单点故障的依赖，增强了整个平台的抗攻击能力和稳定性。

## 系统总体设计结构
![数据价值交换中心模块设计](https://cdn.nlark.com/yuque/0/2024/png/38896662/1720314642983-eca106ad-5f2c-4c1a-80a6-1af0168e275c.png#averageHue=%23f4f4f4&clientId=u653dedcb-2970-4&from=paste&height=371&id=u7cab9f16&originHeight=742&originWidth=1348&originalType=binary&ratio=2&rotation=0&showTitle=true&size=152530&status=done&style=none&taskId=u11ecc1ba-978f-48c4-8b88-b51c0f2d02d&title=%E6%95%B0%E6%8D%AE%E4%BB%B7%E5%80%BC%E4%BA%A4%E6%8D%A2%E4%B8%AD%E5%BF%83%E6%A8%A1%E5%9D%97%E8%AE%BE%E8%AE%A1&width=674 "数据价值交换中心模块设计")

数据交换中心将提供身份认证、隐私计算、数据目录管理、数据接收、转换发送、日志管理等功能。针对上述功能，分布式数据交换中心应包括：四个大的模块，它们分别是共享模块、身份模块、结果处理模块、以及区块链模块。<br />其中共享模块中的数据发送服务将数据交换区的文件转化为合适的JSON格式后，进行压缩与加密发送出去。隐私集合求交服务、隐私信息检索服务、自定义多方安全学习服务用于实现隐私计算场景，控制进行隐私计算参与方的隐私计算工具与通信，实现隐私计算任务。数据目录权限管理服务用于管理系统中总数据目录的访问权限。数据目录存储服务用于汇总并存储各个交换代理点的数据目录，方便查看其他各个代理点的数据文件。<br />身份认证模块主要包含两个服务，一个是身份认证服务用于核验每一次请求接受时，发起者的身份确认，另一个是身份管理服务，主要用于身份信息的存储与管理。<br />结果处理模块中的数据接受服务通过解析发送过来的JSON格式数据，转化为对应的文件，存储到结果处理区当中，方便后续对结果的操作。结果管理服务对结果处理区中的文件进行管理，提供上传，下载，删除等一系列操作。<br />区块链模块中的日志生成服务对中心接受或发送行为进行记录，将请求的元数据（请求概述，发起者，接受者，请求时间等）形成统一的日志。通过日志上链服务将记录上链进行存证，并可以通过日志溯源服务查看之间的操作日志。<br />![数据价值交换代理模块设计](https://cdn.nlark.com/yuque/0/2024/png/38896662/1720314791793-5b4405d3-34c6-42e7-9bdb-1300e512fb31.png#averageHue=%23f3f3f3&clientId=u653dedcb-2970-4&from=paste&height=371&id=u0aeb7c98&originHeight=742&originWidth=842&originalType=binary&ratio=2&rotation=0&showTitle=true&size=107958&status=done&style=none&taskId=u046fd00c-ec21-4792-87ed-212a7889d9b&title=%E6%95%B0%E6%8D%AE%E4%BB%B7%E5%80%BC%E4%BA%A4%E6%8D%A2%E4%BB%A3%E7%90%86%E6%A8%A1%E5%9D%97%E8%AE%BE%E8%AE%A1&width=421 "数据价值交换代理模块设计")	

数据价值交换代理的功能模块与交换中心类似，主要由于其本身不接受具体文件，缺少结果处理模块。在共享模块中，代理点主要通过数据目录生成服务提供数据交换区的数据目录，并通过数据目录同步服务将数据目录发送给数据交换中心进行数据目录的管理。

## 服务设计
<a name="uagnP"></a>
### 数据发送服务设计
考虑到数据在传输过程的安全性和传输性能问题。所以在数据发送之前需要先对数据进行加密和压缩。如果要发送的数据比较大，还需要对JSON的数据进行分割。分割后的JSON必须仍然能够满足JSON文档有效性和保持所存储数据的不变性。 <br />数据发送服务接收映射模块生成的JSON格式数据后，首先对数据进行加密，然后压缩加密后的数据，最后把压缩后的数据发送。
<a name="Xbh3t"></a>
### 数据目录同步服务设计
该模块负责监控数据目录的变化，通过相关接口发送数据目录的同步请求，请求大致可以分为三类，数据目录的增加/修改/删除。对于增加请求，请求中需要提供提新目录的ID和父目录ID；对于修改请求，请求中需要提供待修改的目录ID和新的目录ID；对于删除请求，需要提供待删除的目录ID。
<a name="j3ilc"></a>
### 数据目录生成服务设计
数据目录生成服务根据代理点的文件交换区与关系数据库生成对应的数据目录，数据目录按文件树的形式展现，文件树例子如下：
```yaml
/法院数据
├── 判决文书-绝密
│   ├── 2024
│   │   ├── 判决文书_案件编号1.json
│   │   ├── 判决文书_案件编号2.json
│   │   └── ...
├── 卷宗
│   ├── 刑事案件
│   │   ├── 卷宗_案件编号1.doc
│   │   ├── 卷宗_案件编号2.doc
│   │   └── ...
├── 法律法规
│   ├── 法律法规1.txt
│   ├── 法律法规2.txt
│   └── ...
└── 人员名单
    ├── 犯罪人名单.csv
    └── 嫌疑人名单.csv

```
除开基本的文件树，数据目录中应该包含通过关系数据库得到的文件元数据（文件的描述、文件修改时间、文件大小、文件操作权限、文件表头等）
<a name="pw1sS"></a>
### 数据目录存储管理服务设计
数据交换代理将自己的数据目录以JSON的形式发送给数据交换中心，数据交换中心对每个数据目录JSON文件进行还原，形成一个统一的大文件树形式统一存储。除开基本的文件树，数据目录中应该包含文件元数据（文件的描述、文件修改时间、文件大小、文件操作权限、文件表头等）。
<a name="AUmpF"></a>
### 数据目录权限管理服务设计
数据交换中心还可以管理数据目录的权限，对数据目录的权限进行分配，这样可以控制各个数据代理节点在文件传输，隐私计算等任务能够选择的数据。

#### 可信信道建立

#### 隐私信息检索
通过在平台中嵌入精确的隐私信息检索（PIR）功能，办案部门可以在不直接暴露个人信息的情况下，查询特定案件的关键信息。交换中心首先查看自身数据目录，查看可以进行隐私信息检索的文件。选取好对应的文件之后将请求发送给对应的交换代理，交换代理在验证交换中心的身份后，由中心控制进行PIR协议的运行，运行结果返回存储在交换中心的结果管理区中。<br />PIR的实施确保了各部门之间隐私信息的安全交换与及时性，这对于维护个人隐私权，确保案件的合法性和公正性至关重要。同时，高效的隐私信息检索能够显著降低不必要的信息暴露，加快案件敏感数据的安全处理流程。这不仅符合隐私保护的最佳实践，也符合当下对数据保护日益严格的法律法规要求。<br />以两方PIR为例，我们流程图如下所示：<br />![隐私信息检索](https://cdn.nlark.com/yuque/0/2024/png/38896662/1720323643340-90bef2bc-5d04-4204-8b66-2260fb7dae6b.png#averageHue=%23f7f7f7&clientId=u653dedcb-2970-4&from=drop&height=339&id=uf2129029&originHeight=644&originWidth=1130&originalType=binary&ratio=2&rotation=0&showTitle=true&size=176010&status=done&style=none&taskId=u38d84694-4253-4dac-9565-85c88e19655&title=%E9%9A%90%E7%A7%81%E4%BF%A1%E6%81%AF%E6%A3%80%E7%B4%A2&width=595 "隐私信息检索")

#### 隐私集合求交
隐私集合求交（PSI）是一种技术，允许多个数据持有者在不透露自身数据的前提下，找出共有的元素。交换中心首先查看自身数据目录，查看可以进行隐私信息求交的文件。选取好对应的文件之后将请求发送给对应的交换代理，交换代理在验证交换中心的身份后，由中心控制进行PSI协议的运行，运行结果返回存储在交换中心的结果管理区中。<br />对于多个部门间的数据协同，PSI提供了一种安全的技术手段，使各部门能够在保留各自数据主权的同时，进行联合分析和研究。这不仅有助于打破数据孤岛，还能最大化地发挥数据的价值。<br />以两方PSI为例，我们流程图如下：<br />	![隐私集合求交](https://cdn.nlark.com/yuque/0/2024/png/38896662/1720324771892-7bf89d7a-9acf-4ea1-8fd8-decff55842a6.png#averageHue=%23f7f7f7&clientId=u653dedcb-2970-4&from=drop&height=272&id=ub6b97526&originHeight=644&originWidth=1130&originalType=binary&ratio=2&rotation=0&showTitle=true&size=179350&status=done&style=none&taskId=uc8614436-cab0-44c9-94fb-807ed7dc038&title=%E9%9A%90%E7%A7%81%E9%9B%86%E5%90%88%E6%B1%82%E4%BA%A4&width=477 "隐私集合求交")

#### 自定义安全多方计算
除了上述提到的具体场景，为了应对更复杂的隐私计算应用场景，用户可以自行编写安全多方计算（MPC）程序，实现平台未预置的一般性功能。这些功能包括但不限于：机器学习模型的训练与推理、隐私保护下的数据统计分析以及更广泛的安全多方计算任务。这使得数据交换平台具备了强大的扩展性和灵活性。<br />交换中心首先查看自身数据目录，查看可以进行MPC的文件，并编写好对应的MPC源码，选取好对应的文件之后将请求与源码发送给对应的交换代理，交换代理在验证交换中心的身份后，由中心控制进行MPC协议的运行，运行结果返回存储在交换中心的结果管理区中。<br />以两方MPC隐私计算为例，我们流程图如下：<br />![自定义安全多方计算](https://cdn.nlark.com/yuque/0/2024/png/38896662/1720324989282-a9a02a07-d826-45dc-a0ce-c8fb04e0ad6b.png#averageHue=%23f6f6f6&clientId=u653dedcb-2970-4&from=drop&height=296&id=u61c09ed7&originHeight=646&originWidth=1136&originalType=binary&ratio=2&rotation=0&showTitle=true&size=182404&status=done&style=none&taskId=ucfd6b8d5-9e47-4ba9-9959-3f9bc1575f2&title=%E8%87%AA%E5%AE%9A%E4%B9%89%E5%AE%89%E5%85%A8%E5%A4%9A%E6%96%B9%E8%AE%A1%E7%AE%97&width=520 "自定义安全多方计算")

### 结果处理模块
<a name="aQNWa"></a>
#### 结果下载
数据交换后的结果会存储在数据交换平台中的结果管理区中，数据接收方（比如法院、检察院等）的业务系统需要从结果管理区将数据结果下载到本地。 下载后的数据将被整合到各自的业务系统中，以供后续处理和分析。数据结果的下载和整合过程应遵循严格的安全和合规标准，以确保数据的完整性和保密性。  <br /> 自动化的数据下载和集成减少了人工操作的时间和错误，确保各部门能够迅速获取所需信息，加快案件处理和行政事务的进展。  另外， 通过安全的下载和存储机制，可以确保敏感司法数据在传输和存储过程中的保密性和完整性，符合相关法律法规的要求，防止数据泄露和不当使用。  <br />业务系统进行结果下载的流程图如下所示：<br />![结果下载](https://cdn.nlark.com/yuque/0/2024/png/38910942/1720338988984-0fb67184-9983-4bd4-97cd-15b103abed06.png#averageHue=%23f9f9f9&clientId=u7e53dad7-b1aa-4&from=paste&height=344&id=ue9e4979b&originHeight=671&originWidth=747&originalType=binary&ratio=1.5&rotation=0&showTitle=true&size=39031&status=done&style=none&taskId=u5d939685-2a6e-46a4-b6e0-6af2313c4cf&title=%E7%BB%93%E6%9E%9C%E4%B8%8B%E8%BD%BD&width=383 "结果下载")
<a name="Lhrah"></a>
#### 结果删除
业务系统在对数据交换平台的结果管理区进行查询后，如果发现某些文件出现冗余或不再需要，则需要对数据交换中心发起对应文件的结果删除请求，数据交换中心在结果管理区中删除相应的文件。<br /> 删除冗余或不再需要的文件，可以显著优化数据管理，减少结果管理区存储空间的占用，提升系统性能。  同时也可以使得数据接收方在进行查询和检索时更加高效，快速找到所需的有效信息。  <br />业务系统进行结果删除的流程图如下所示：<br />![结果删除](https://cdn.nlark.com/yuque/0/2024/png/38910942/1720339103198-4528008f-83f1-4f4c-85c8-282788867d71.png#averageHue=%23fafafa&clientId=u7e53dad7-b1aa-4&from=paste&height=282&id=u7fef8663&originHeight=542&originWidth=771&originalType=binary&ratio=1.5&rotation=0&showTitle=true&size=31547&status=done&style=none&taskId=u4aeb837b-0abc-4223-ab03-2afa6d15e0f&title=%E7%BB%93%E6%9E%9C%E5%88%A0%E9%99%A4&width=401 "结果删除")
